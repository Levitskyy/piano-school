# План реализации функциональной части

> Рабочий документ по [ТЗ для coding-агента](online-piano-school-agent-spec.md).
> Фундамент и утверждённые решения — [project-foundation.md](project-foundation.md).
> Исходный бриф — [piano-school-project.md](piano-school-project.md).

## 1. Аудит текущего состояния

На момент начала работ в репозитории уже было:

- монорепо `apps/web`, `apps/api`, `infra/`;
- публичный лендинг на Next.js с академичным визуальным стилем;
- юридические заглушки `/oferta` и `/privacy`;
- FastAPI с health-check, настройками, async SQLAlchemy и Alembic;
- PostgreSQL и Redis в Docker Compose;
- CI, Ruff, pytest, ESLint, TypeScript.

Чего не было:

- пользователей, ролей и авторизации;
- защищённых кабинетов;
- моделей курсов, продуктов, заказов, занятий и домашних заданий;
- платёжной интеграции, загрузки файлов и email-провайдера.

## 2. Что сделано на Этапе 1

- Сохранено новое ТЗ в `docs/online-piano-school-agent-spec.md`.
- Добавлены модели `User`, `StudentProfile`, `UserSession`, `PasswordResetToken`.
- Пароли хранятся как Argon2id-хеши, сессии — в httpOnly-cookie, в БД лежит только SHA-256-хеш токена.
- Реализованы регистрация, вход, выход, `GET /auth/me`, восстановление пароля и смена пароля по одноразовой ссылке.
- Добавлены роли `student`, `teacher`, `admin` и серверные проверки доступа.
- Добавлен профиль ученика: имя и часовой пояс.
- Сделан same-origin BFF `/api/*` в Next.js: браузер общается только с web-сервером, FastAPI не нужно открывать в домашнюю сеть.
- Добавлены страницы `/login`, `/register`, `/forgot-password`, `/reset-password`.
- Добавлены защищённые каркасы `/account`, `/teacher-panel`, `/admin`; список пользователей в админке уже читается из API.
- Настроены миграции и тесты API.

### Ограничения Этапа 1

- Email-провайдер не выбран. В `local` ссылка восстановления возвращается в ответе API; в production восстановление вернёт 503, пока не появится реальный адаптер почты.
- Есть базовый fixed-window rate limiting в Redis для входа, регистрации и восстановления пароля. Подтверждение email и более строгая защита от распределённого перебора — задачи этапа безопасности.
- Каталог, курсы, заказы, оплата, занятия и домашние задания пока представлены заглушками.
- Лендинг намеренно не переписывался; добавлена только ссылка «Войти».

## 3. Расхождения и решения

| Тема | Решение на 19.11.2026 |
|---|---|
| Ежемесячное сопровождение | Входит в MVP как второй вариант покупки одного курса, без автопродления. Период сопровождения фиксированный, состав и продление уточняются |
| Платёжный провайдер | ЮKassa, RUB-only |
| Роли | Ученик, преподаватель, администратор; разделение teacher/admin реализовано |
| Профили детей | В MVP один взрослый аккаунт; в `StudentProfile` есть nullable `parent_user_id` |
| Программа | Один курс фортепиано с модулями и уроками; два варианта покупки |
| Хранение видео | S3 + HLS; production-кандидат Yandex Object Storage, локально MinIO |
| Email | Unisender Go; адаптер реализован, production включается через настройки |
| Авторизация | Серверные opaque-сессии; JWT отложен |

## 4. План этапов

### Этап 2. Модель контента и каталога — частично реализован

Сделано:

- `Course` с двумя `CourseOffer`: самостоятельное обучение и сопровождение.
- `CourseModule`, `Lesson`, `LessonMaterial`, `CourseAccess`, `LessonProgress`.
- Миграции применены.
- Публичные API: список курсов, карточка курса, программа.
- Кабинет: список доступных курсов и прогресс.
- Защищённая страница урока с отметкой прогресса.
- Демонстрационный курс через `make seed-demo`.
- Ручная выдача доступа через `make grant-access`.

Осталось:

- Админ-CRUD курсов, модулей, уроков и материалов.
- Загрузка файлов и видео.
- Подписанные ссылки на материалы.

Критерий готовности: можно создать семестр с модулями и уроками, он отображается в каталоге и защищённом кабинете.

### Этап 3. Публичные страницы и кабинет обучения — частично реализован

Сделано:

- `/courses` — каталог.
- `/courses/[slug]` — описание, программа, варианты покупки, CTA.
- `/courses/[slug]/lessons/[lessonSlug]` — защищённая страница урока.
- В кабинете: список доступных курсов, программа, прогресс.
- Заглушка плеера, материалы и отметка прогресса.
- Без доступа — 403/редирект на вход.

Осталось:

- HLS-плеер и подписанные URL.
- Приватные ссылки на материалы.
- Страница продолжения с последнего места.

Критерий готовности: ученик с выданным доступом открывает урок и материалы; без доступа получает 403/редирект.

### Этап 4. Сопровождение

- Сопровождение не является отдельной подпиской: второй вариант покупки курса.
- В кабинете: статус периода, загрузка работ, ответы преподавателя.
- В панели преподавателя: очередь работ и текстовые комментарии.

До реализации нужно подтвердить: что именно входит в период, лимиты, правила продления и возврата.

### Этап 5. Индивидуальные занятия

- `IndividualLessonOffer`, `LessonSlot`, `LessonPackage`, `LessonBooking` — реализованы.
- Публичная страница `/individual-lessons`: тарифы 1/4/8 уроков по 60 минут, слоты в часовом поясе ученика.
- Тестовая покупка без списания денег: слот подтверждается сразу, пакет создаётся, первое занятие списывается.
- Остаток пакета используется для записи на следующие слоты из кабинета.
- Одно занятие в день на ученика: дни с существующей записью скрываются в календаре, повторная запись на тот же день отклоняется API.
- В панели преподавателя `/teacher-panel/lessons` видны все записи учеников; ссылка на встречу добавляется и редактируется там же.
- По роли `teacher` доступны только панель преподавателя и её API; ученические разделы остаются закрытыми.

До запуска нужно подтвердить: финальные цены, расписание, длительность, правила отмены, срок действия пакета и подключить ЮKassa вместо тестового подтверждения.

### Этап 6. Оплата, файлы, уведомления и запуск

- ЮKassa: создание платежа, webhook с проверкой подписи, идемпотентность, возвраты.
- Выдача доступа только после подтверждённого платежа.
- S3-хранилище, приватные подписанные ссылки, лимиты загрузки.
- Email-провайдер: Unisender Go; шаблоны писем.
- Видео: S3 + HLS, production-кандидат Yandex Object Storage.
- Усилить rate limiting (по IP и аккаунту), подтверждение email, аудит действий, бэкапы.
- Sandbox-тесты, проверка ролей, мобильных устройств и часовых поясов.
- Юридика перед продом: заполнить и опубликовать финальные `/oferta`, `/privacy`, `/contacts`, согласия в UI, условия возвратов, настройки чеков 54-ФЗ (см. чек-лист в `docs/project-foundation.md`, раздел 10).
- Production checklist и инструкция администратору.

## 4.1. Запуск только индивидуальных занятий (решения от 22.11.2026)

- `COURSES_ENABLED=false` скрывает курсы на уровне страниц (404), навигации и API.
  Ветки под запуск нет: прод и локальное окружение отличаются переменной окружения.
- Покупка урока/пакета создаёт заказ и резервирует слот, затем создаёт платёж ЮKassa
  на итоговую сумму. Бронь и пакет появляются только после подтверждённого платежа.
- Промокод одноразовый и процентный: применяется до создания платежа, итог округляется
  до рубля; код создаётся CLI-командой `make promo-code percent=... offer=single` или в
  админке и действует только на выбранный тариф.
- Чеки для самозанятого настраиваются в кабинете ЮKassa: API-код не подставляет
  налоговые коды без подтверждённой документации.

## 5. Технические заметки

- Авторизация использует серверные opaque-сессии, а не JWT. Причины: немедленный logout и отзыв сессий, мгновенное применение смены роли, отсутствие хранения токена в JS, простота BFF. JWT можно добавить позже для публичного API или мобильного клиента.

- Браузер не ходит напрямую в FastAPI. Next.js проксирует `/api/*`, поэтому cookie сессии выдаётся на домене сайта, а API можно держать на `127.0.0.1`.
- Все денежные суммы — целые числа в минорных единицах и код валюты.
- В БД время хранится в UTC; часовой пояс пользователя — отдельное поле.
- Доступ к урокам и файлам проверяется на API, а не только скрытием ссылок в интерфейсе.
- Пароли и сессии не логируются. Токены сброса одноразовые.
- Лимиты входа, регистрации и восстановления пароля хранятся в Redis; при недоступности Redis защита не блокирует вход, но это нужно мониторить.
- Для production нужны `Secure` cookie, HTTPS, реальный `SECRET_KEY` и настроенный email-провайдер.
