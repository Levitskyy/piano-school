## 1. Цель

Сайт преподавателя фортепиано, который продаёт видеокурсы, разовые уроки и пакеты уроков и автоматически выдаёт доступ после оплаты — без ручного участия преподавателя. MVP за 1–2 месяца, затем развитие по обратной связи.

## 2. Подтверждённые решения

| Вопрос | Решение | Следствия |
|---|---|---|
| Продавец | ИП или самозанятый в РФ | Российский эквайринг, чеки по 54-ФЗ, договор-оферта и политика по РФ |
| Эквайринг RUB | ЮKassa | Webhooks с проверкой подписи, идемпотентная обработка, возвраты через API |
| Международные платежи | Только этап 2 | В MVP принимаем RUB; цены в USD/EUR не принимаем, автоматическую конвертацию не делаем |
| Разработка | Владелец + AI-агент | Минимум инфраструктуры, простые решения, всё документируется в репозитории |
| Домашние задания | Упрощённо в MVP | Загрузка файла учеником + текстовый комментарий преподавателя. Без плеера, оценок и веток обсуждения |
| Курс | Один курс фортепиано с двумя вариантами покупки | Самостоятельное обучение и сопровождение преподавателя; сопровождение включается на фиксированный период, без автопродления |
| Ссылка на урок | Вручную в админке | Преподаватель вставляет ссылку Zoom/Meet после подтверждения слота; автогенерация — этап 2 |
| Хостинг | VPS + Docker Compose | Nginx/Caddy, CI/CD, бэкапы БД и файлов — на нашей стороне |
| Бренд | Название есть, лого и фото — нет | Временный текстовый логотип и заглушки; бренд-кит позже |
| Язык интерфейса | Русский | Тексты выносим в словари, архитектура с заделом на локализацию |
| Первый запуск | Только индивидуальные занятия и пакеты | Курсы скрыты флагом `COURSES_ENABLED=false`: страницы и API курсов возвращают 404, ссылки убраны. Один код, продакшен отличается переменной окружения |
| Промокоды | Одноразовые процентные, создаются CLI или в админке и привязаны к одному тарифу | Применяются только к покупке выбранного тарифа: 100%-код на разовый урок не сработает на пакет. Итог считается на бэкенде, округляется до рубля и передаётся в ЮKassa |
| Чеки для самозанятого | Настраиваются в кабинете ЮKassa | Код не передаёт `tax_system_code`: без подтверждённой документации не выдумываем налоговые коды |

## 3. Технические решения каркаса

Это рабочие гипотезы из брифа, принятые для старта. Поменять их сейчас дешево, после запуска — дорого.

| Слой | Решение |
|---|---|
| Frontend | Next.js 16 (App Router), React 19, TypeScript, SSR публичных страниц |
| Backend | FastAPI, Pydantic v2, OpenAPI |
| БД | PostgreSQL 17, SQLAlchemy 2.1 (async), Alembic |
| Очереди | Redis 8 + ARQ (транскодирование, email, webhooks, освобождение броней) |
| Файлы | S3-совместимое хранилище, приватный доступ по подписанным URL |
| Видео | HLS, несколько качеств, выдача через подписанные URL/CDN |
| Авторизация | Email + пароль, серверная сессия в httpOnly-cookie, пароли — Argon2id | В БД хранится SHA-256-хеш opaque-токена. JWT не вводим: нужна немедленная отзываемость, смена ролей и простота; JWT оставлен для будущего публичного API/мобильного клиента |
| Деньги | Целое число в минорных единицах + код валюты; отдельная цена на каждую валюту, без автоконвертации |
| Время | В БД — UTC; пользователю показываем в его часовом поясе; расписание преподавателя хранится с его TZ |
| API | REST, типизированный TS-клиент генерируется из OpenAPI |
| Доступ браузера к API | Same-origin BFF в Next.js | Браузер вызывает `/api/*`, Next проксирует в FastAPI; API не публикуется в домашнюю сеть |
| Репозиторий | Монорепо: `apps/web`, `apps/api`, `packages/*`, `infra/*` |
| Инструменты | pnpm + uv, Ruff, pytest, ESLint, GitHub Actions |

## 4. Состав MVP

1. Лендинг, каталог, страница курса с двумя вариантами покупки, тарифы, оферта и политика конфиденциальности.
2. Регистрация/вход, личный кабинет.
3. Курсы: модули и уроки, плеер HLS, PDF-ноты и материалы, отметки прохождения, прогресс, продолжение с последнего места.
4. Оплата курсов через ЮKassa (RUB), автоматическая выдача доступа через webhook.
5. Расписание: рабочие часы преподавателя, слоты с учётом часового пояса ученика, бронь на время оплаты.
6. Разовая покупка урока и пакета; остаток занятий; запись на слот из пакета.
7. Ссылка на встречу вручную после подтверждения; email-подтверждения.
8. ДЗ упрощённо: загрузка файла + комментарий преподавателя.
9. Базовая админка: курсы и уроки, расписание, заказы, ученики, остатки пакетов, очередь ДЗ.

## 5. Осознанно отложено

- Приём международных карт и мультивалютные платежи.
- Профили детей внутри аккаунта родителя (в MVP — один взрослый аккаунт).
- Автогенерация ссылок Zoom/Meet и запись уроков.
- Напоминания, правила переноса и отмены сверх простого минимума.
- Многоразовые и администрируемые из UI промокоды, реферальная программа, платная подписка на контент. Ежемесячное сопровождение в MVP не является подпиской: оно входит как второй вариант покупки одного курса на фиксированный период без автопродления.
- Блог, аналитика обучения, PWA/мобильное приложение.
- Отзывы на лендинге.

## 8. Уточнения от 19.11.2026

Новое ТЗ принято как рабочая спецификация функциональной части. Оно расширяет MVP:
появляются шесть семестров, отдельные роли преподавателя и администратора,
ежемесячное сопровождение и заявки на индивидуальные занятия. Публичный лендинг
не переписываем.

### 8.1. Подтверждено для реализации

- Один курс фортепиано — самостоятельный продукт с модулями и уроками; доступны два варианта покупки: самостоятельное обучение и сопровождение.
- Роли: ученик, преподаватель, администратор. Проверка ролей — на сервере.
- Личный кабинет ученика, панель преподавателя и админка — отдельные разделы.
- Регистрация, вход, выход и восстановление пароля через email.
- Профиль ученика хранит часовой пояс.
- Упрощённые домашние задания: файл ученика + текстовый комментарий преподавателя.
- Ссылка на индивидуальную встречу добавляется вручную.
- Оплата в MVP — RUB через ЮKassa, если не будет принято другое решение.

### 8.2. Решения от 19.11.2026 (второй раунд)

| Вопрос | Решение |
|---|---|
| Ежемесячное сопровождение в MVP | Входит, но не как подписка. Один курс фортепиано имеет два варианта покупки: самостоятельное обучение и сопровождение. Сопровождение действует фиксированный период (рабочая гипотеза — 90 дней), без автопродления |
| Платёжный провайдер | ЮKassa подтверждена, RUB-only |
| Email-провайдер | Unisender Go: SMTP или HTTPS API, серверы в РФ, SPF/DKIM через домен отправителя |
| Видео | S3 + HLS подтверждено; production-кандидат Yandex Object Storage, локально MinIO |
| Авторизация | Серверные opaque-сессии в httpOnly-cookie, JWT не используется на MVP |

### 8.4. Текущий статус

Работает Этап 1: регистрация, вход, выход, восстановление пароля, роли, профиль,
защищённые кабинеты ученика, преподавателя и администратора, базовый rate
limiting. Частично реализован Этап 2: модели курса, модуля, урока, материала,
доступа и прогресса; миграции; публичный каталог и карточка курса; список курсов
в кабинете; защищённая страница урока с отметкой прогресса; ручная выдача
доступа через CLI. Оплата, загрузка видео/файлов, календарь, уведомления и
админ-CRUD контента пока не реализованы.

## 9. Решения от 22.11.2026: запуск без курсов и промокоды

- Первый запуск продаёт только индивидуальные уроки и пакеты. `COURSES_ENABLED=false`
  убирает публичные и кабинетные страницы курсов (404) и закрывает курсовые API;
  отдельная git-ветка для этого не используется.
- Оплата уроков и пакетов идёт через ЮKassa (тестовый магазин, RUB). Слот резервируется
  на время оплаты, бронь и пакет создаются только после подтверждённого webhook'а.
- Промокод одноразовый, процентный, создаётся командой `make promo-code percent=... offer=single`
  или в админке `/admin/promo-codes`. При создании обязательно выбирается товар — один из
  тарифов индивидуальных занятий; код действует только на него. Так 100%-скидка на разовый
  урок не применится к пакету из 8 уроков.
  Итоговая сумма считается на бэкенде, округляется до рубля и передаётся в ЮKassa.
  Один заказ — не более одного кода; повторное применение использованного кода отклоняется.
- Коды, созданные до появления привязки к товару, деактивируются миграцией: их назначение
  неизвестно, а свободное применение ко всем тарифам небезопасно. Админ создаёт новые коды
  уже с выбранным тарифом.
- Промокод закрепляется за заказом на время оплаты. Пока заказ не истёк или не отменён,
  другой заказ этот код применить не может.
- Если оплата подтвердилась после истечения резерва и слот уже занят, платёж не теряется:
  оплаченное занятие остаётся в пакете ученика, и он выбирает новое время в кабинете.
  Слот, который всё ещё свободен, закрепляется за оплаченным заказом.
- `release_expired_orders` проверяет статус платежа в ЮKassa перед освобождением слота:
  незавершённый платёж продлевает резерв, отменённый — освобождает слот и промокод.
  Дополнительно задача запускается воркером каждые 5 минут.

### Отмена и перенос занятий

- Ученик может отменить или перенести занятие не позднее чем за 24 часа до начала.
  Порог настраивается переменной `LESSON_CANCELLATION_HOURS` (по умолчанию 24).
  Ближе к занятию отмена и перенос доступны только через преподавателя.
- При отмене слот освобождается, а урок возвращается в пакет. Исчерпанный пакет
  снова становится активным, если срок его действия не истёк.
- Перенос не меняет остаток уроков: старый слот освобождается, новый занимается,
  занятие остаётся в том же пакете, ссылка на встречу сбрасывается.
- Преподаватель и админ могут отменить занятие без ограничения по времени — но только
  до его начала. Урок также возвращается в пакет ученика.
- Отменённые записи остаются в истории и не мешают занять слот заново: уникальность
  действует только для подтверждённых записей.
- В кабинете ученика у подходящих занятий есть кнопки «Перенести» и «Отменить»;
  в панели преподавателя — «Отменить занятие».

### Что осталось открытым

- Точные цены тарифов 1/4/8 уроков и финальные тексты оферты/политики — до приёма реальных платежей.
- Настройка чеков для самозанятого в кабинете ЮKassa — до первого реального платежа:
  код пока не передаёт налоговые коды и не формирует чек сам.
